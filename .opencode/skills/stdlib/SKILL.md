# Hella Standard Library

Guide for building `stdlib` for Hella (EBNF draft 0.1).

## Core Decisions (locked)

1. **Pure Hella sources** — stdlib is Hella code under `stdlib/` (e.g. `stdlib/std/io.hll`), not hand-written LLVM IR. Runtime `extern "c"` helpers live in `runtime/` only when Hella cannot express an operation.
2. **Import semantics confirmed — EBNF §32** — `import qualified-name [:: "{" import-list "}"] statement-terminator` is canonical. Qualified path `a::b::c` maps to `stdlib/a/b/c.hll`. No alternate syntax.
3. **Go with proposal** — phased approach from `references/phases.md` + LLVM mapping (`references/llvm-mapping.md`). Stdlib blocks on Phase 5 capabilities (generics, FFI) without inventing workarounds.
4. **Respect compiler limits** — concrete collection facades, byte strings, streaming split and bool/ref integer parsing; no invented generic ownership API.

## EBNF §32 Contract + where modules live

```
import-declaration =
    "import" , qualified-name , [ "::" , "{" , import-list , "}" ] , statement-terminator ;

import-list = identifier , { "," , identifier } ;
qualified-name = identifier , { "::" , identifier } ;
```

* `import std::io` → whole module.
* `import std::io::{print, println}` → selected symbols (resolver filters; sema still sees only selected; the module's `extern` blocks always ride along).
* Resolution (`crates/hella-compiler/src/modules.rs`, shared by CLI and LSP), in order:
  1. **Project root** — nearest ancestor containing `main.hll` (else the
     entry's own directory). `import foo` → `foo.hll` (else `foo/mod.hll`);
     `import net::http` → `net/http.hll`. Cycles cut by visited-file set.
  2. **Dev checkout** — ancestor `stdlib/` (repo work uses live sources).
  3. **`~/.hella/lib`** (UNIX) — populated by `hella setup` (embedded
     `stdlib/**/*.hll`, list auto-generated by `hella/build.rs`).

## Current Phase (real stdlib: IO owned by `stdlib/`)

**Shipped (`stdlib/std/io.hll`) — pure Hella, no compiler intrinsics:**
- `void print(string s)` — no newline, via `extern i32 printf(string fmt, ...)`
- `void println(string s)` — with newline, via `extern i32 puts(string s)`
- `void eprint` / `void eprintln(string s)` — stderr via
  `extern int write(int fd, string buf, int count)` on fd 2 (no `FILE*`
  global, portable macOS/Linux)
- `string readLine()` — dynamically growing, bounded one-byte scans; blank lines
  and EOF are supported. EOF/error still lack a separate status.
- Numeric input uses `std::num::parseInt` (import `std::num`, then call
  `parseInt(input, ref value)`) with explicit bool failure and overflow checks.

**Current API / migration / caveats:** `stdlib/README.md` is authoritative.
Typed format and IO helpers have been removed; use interpolation and print/println.
Interpolation itself still needs compiler safety fixes; library composition uses
checked-size byte copying instead. All stdlib examples run in the new compiler
integration test `crates/hella-compiler/tests/stdlib.rs`.
See `REAL_STDLIB.md` for the boundary rule.

Implementation note: Hella `string` is `ptr (i8*)` null-terminated in
`codegen/mod.rs`. `extern` §36 is stable, so stdlib declares libc directly and
the compiler lowers ordinary calls (plus `module.get_function` fallback for
`extern` callees). Sema has no `print`-family shortcut: without
`import std::io` these names are `undefined function` by design. See
complementary skill `hella-stdlib-real` (`REAL_STDLIB.md`) for the full
compiler-owns vs stdlib-owns contract.

## Workflow When Extending Stdlib

1. Add `stdlib/std/<mod>.hll` as pure Hella (type-first `int x`, `do…end`, `has…end`).
2. If new module needs FFI, add `extern` block per EBNF §36 and corresponding `runtime/*.c`.
3. Update `parse` for any new syntax the module uses, then `sema` (name resolution), then `codegen` (LLVM lowering + `module.verify()`).
4. Add `examples/stdlib_<mod>.hll` that `import std::<mod>` and is compiled+linked as regression.
5. Keep `stdlib/README.md` symbol index in sync.

## Testing

- Unit: `cargo run -- <example>.hll` → `./example.out` and check stdout.
- Example: `examples/stdlib_io.hll` imports `std::io` and calls each shipped function.
- CI: verify `module.verify()` never skipped before `write_to_file`.

## Anti-Patterns

- No Rust-implemented stdlib shims that bypass Hella source (except tiny `runtime/` C helpers).
- No `import` syntax outside EBNF §32.
- No stdlib feature that requires generics/traits/closures before Phase 5 monomorphization exists.
- No `{}` blocks or `let` — stdlib uses Hella surface (`do…end`, `int x = …`).

## Future Roadmap (deferred)

- Module resolver: caching, visibility `public`/`private` enforcement. (Cycle detection DONE via visited-file set.)
- String ABI switch to `{ptr,i64}` length struct (breaks current `ptr`).
- `extern` FFI (§36) → DONE for IO: stdlib declares libc directly via
  `extern` blocks; compiler only lowers them (no intrinsification).
  Remaining: `FILE*`/stderr plumbing for `eprint`, string-buffer append for `readLine`.
- Generics → `std::vec`, `std::option`, `std::result`.
- Traits / extensions → `extend string do … end` helpers.
