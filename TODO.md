## `hellastamp` file

Sidecar next to each built binary, e.g. `out/debug/app` → `out/debug/app.hellastamp` (`crates/hella-cli/src/main.rs:1035` `stamp_path`, `1041` `stamp_contents`, `1049` `write_build_stamp`, `1056` `is_fresh`).

Content:
```
profile=debug|release
toolchain=hella <version>  # Cargo.toml version
```

Purpose: `hella run` freshness — rebuild is skipped only when the binary is newer than **all** source files (`expand_imports` list via `hella_compiler::modules`) **and** the stamp matches current `profile`/`toolchain`; otherwise profile/version switch or touched source forces rebuild. `out/` is VCS-ignored (`.gitignore` `/out/`).

## Async — structured concurrency (v1 SHIPPED 2026-09-18; see scope notes)

Shipped model (deviation from the stackless plan, deliberate): `async` bodies run as **thread-backed tasks** (`runtime/hella_async.c`, pthreads/Win32) instead of stackless state machines with a single-threaded executor. Every contract the plan called out holds — explicit suspension points, scoped child tasks, single-owner `task<T>`, no lazy `Future<T>`, no detached tasks, and reachability-based runtime inclusion — but `await` is a blocking join on the calling thread rather than a state-machine suspension, and the executor is the OS scheduler with cooperative `yield`/`sleepMs` checkpoints. Stackless frames (needed for cheap concurrency and true suspension) remain future work; that is the main deferred piece, along with async I/O, channels/select, async closures, and detached tasks.

`async` goes immediately before `do`: `int delayedValue(int value) async do ... end` and `void main() async do ... end`. Calls to async functions from an async body spawn them and yield a `task<T>` handle; `spawn` is the explicit form and additionally requires an enclosing `scope do ... end`. Handles are single-await and scope-bound; scope exit is the join point.

The compiler automatically includes the async runtime only when the program actually uses async code (`crates/hella-compiler/src/async_req.rs`, call-graph reachability from `main`/`init`/globals — not keyword scanning, not dead stripping). Merely importing a module containing unused async declarations does not pull it in; synchronous programs reference no scheduler symbols.
